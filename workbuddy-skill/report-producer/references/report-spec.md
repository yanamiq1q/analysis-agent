# ReportSpec 字段说明（v1.0）

报告包是一个 JSON 文件（`report.json`）。你（宿主）只需要读它，**不要修改任何数值**。

## 顶层

| 字段 | 含义 | 用法 |
|---|---|---|
| `schema_version` | 契约版本，当前 `1.0` | 不是 1.0 就停下，告诉用户不兼容 |
| `job_id` | 任务 id | 排查问题时带上 |
| `template` | 模板名 | 封面页脚可标注 |
| `title` | 报告标题 | 封面主标题 |
| `period.start` / `period.end` | 半开区间 `[start, end)` | 封面写"2026-10-01 ~ 2026-10-31"时，end 要减一天 |
| `sections` | 章节数组 | 按数组顺序出页 |
| `meta` | 生成信息 | 附录用 |

## section

| 字段 | 含义 | 用法 |
|---|---|---|
| `id` | 稳定标识 | 用于定位，不展示 |
| `heading` | 章节标题 | 页面标题 |
| `narrative` | 一句话结论 | 直接放在标题下方；**不要改数字** |
| `metrics` | 指标数组 | 核心指标卡 / 关键数字 |
| `tables` | 表格数组 | 明细页 |
| `charts` | 图表数组 | 趋势/结构页 |
| `caveats` | 口径说明数组 | **必须**出现在页脚或附录 |
| `skipped` | 非空 = 这节没生成 | 用这句话说明原因，不要编数据 |

## metric

| 字段 | 含义 | 展示建议 |
|---|---|---|
| `name` | 指标键（如 `gmv`） | 内部用 |
| `label` | 显示名（如 `GMV`） | 直接展示 |
| `value` | 数值（number 或 null） | 按 `format` 格式化；`null` 显示"—" |
| `unit` | 单位（元 / 单 / 空） | 跟在数值后面 |
| `format` | `money` / `int` / `percent` / `auto` | `percent` 的 0.711 要显示成 71.1% |
| `definition` | 口径说明 | 指标卡下方小字或附录 |
| `compare` | 环比/同比（可能为空） | 见下节，**只展示，不重算** |

## compare（环比 / 同比）

`metrics[].compare` 可能不存在（模板没要求对比），也可能有 `mom`（环比）/ `yoy`（同比）：

```jsonc
"compare": {
  "mom": {
    "prev": 1700000, "delta": 146900, "pct": 0.0864,
    "period": { "start": "2026-09-01", "end": "2026-10-01" },
    "reason": ""            // pct 为 null 时一定有值
  }
}
```

| 字段 | 含义 | 展示 |
|---|---|---|
| `prev` | 上期值 | 一般不展示，排错时看 |
| `delta` | 差值（`value - prev`） | 可展示为"较上月 +14.69 万" |
| `pct` | 变化率（小数） | `+8.6%` / `-3.2%`；`null` 显示 `—` |
| `period` | 上期区间 | 页脚标注"对比 2026-09-01 ~ 2026-09-30" |
| `reason` | 为什么算不了 | `pct=null` 时**必须展示**（如"上期无数据"） |

**禁止自己用 `value / prev - 1` 重算**：基期为 0、负基数、口径变更都会让手算和契约不一致。

## chart

| 字段 | 含义 | 用法 |
|---|---|---|
| `kind` | `line` / `bar` / `pie` / `scatter` | 决定插什么图 |
| `title` | 图表标题 | 图上方 |
| `image_path` | PNG 相对路径（相对 job 目录） | 用 `job_dir + image_path` 找文件 |
| `data_path` | 图表原始数据 JSON | 需要换图型时读取，不要手写数据 |

## table

| 字段 | 含义 |
|---|---|
| `columns` | 列名数组 |
| `rows` | 二维数组，顺序与 columns 对齐 |
| `source_sql` | 这张表的来源 SQL（附录溯源用） |

## meta

| 字段 | 含义 | 用法 |
|---|---|---|
| `generated_at` | 生成时间 | 封面"数据截至" |
| `tables_used` | 用到的表 | 附录 |
| `queries` | 全部 SQL | 附录（溯源），**不要贴进正文** |
| `skipped_sections` | 跳过的节数 | 有值时在摘要里提一句 |
| `trace_id` | 调用链 id | 出问题时给开发 |

## 三条最容易犯的错

1. **把 `value` 当字符串重新格式化**：`1846900` 是数字，别写成 `"1,846,900 元"` 之后再参与计算。
2. **忽略 `caveats`**：读者看到数字却不知道口径，报告就失去意义。
3. **把 `skipped` 当成空节跳过**：必须显式说明"缺哪张表"，否则用户以为这个月没有数据。
