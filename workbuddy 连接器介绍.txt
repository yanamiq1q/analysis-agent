workbuddy 连接器介绍
MCP 是什么
MCP（Model Context Protocol，模型上下文协议）用于把外部工具和服务接进 WorkBuddy，让 AI 获得发送通知、连接业务系统、访问数据源这些扩展能力。

官方的比喻是「AI 的 USB 接口」——就像电脑通过 USB 连外设，MCP 让 AI 连各种外部工具和数据源。

WorkBuddy 已经把 MCP 配置集成到界面里，不需要编码、不需要手动改配置文件，可视化操作就能完成接入。

它带来什么
能力	说明
上下文共享	向模型提供文件内容、数据库记录、业务信息等上下文
工具调用	把文件读写、接口调用、消息发送等能力暴露给模型
可组合工作流	多个工具和服务通过 MCP 串联，组成自动化流程
数据控制	支持本地或受控方式运行，兼顾灵活性与安全性
想找现成的 MCP 服务，可以去腾讯云 MCP 市场看看开放生态里有什么。

两个配置级别
级别	适用场景	配置文件路径
用户级	配置一次，所有项目复用	~/.workbuddy/mcp.json
项目级	仅当前项目生效，互不影响	<项目目录>/.workbuddy/mcp.json
怎么选：

频繁跨项目使用的能力 → 用户级。企微机器人通知、公共知识库这类，配一次全局能用。
仅特定项目需要的专属服务 → 项目级。客户 A 的 CRM 接口不应该出现在客户 B 的项目里。
完整示例：接入企微机器人
以企业微信机器人（WeCom Bot）为例走一遍完整流程。这是官方推荐的入门 MCP——路径清晰、结果立刻可见。

1）获取 WebHook URL
在企业微信群里：添加群机器人 → 获取 WebHook URL。

地址长这样：


https://qyapi.weixin.qq.com/cgi-bin/webhook/send?key=xxxxxxxx-xxxx-xxxx-xxxx-xxxxxxxxxxxx
2）打开 MCP 配置入口
侧边栏「插件」→ 右上角「MCP 服务器」→「配置 MCP」。

3）填写 mcp.json
把下面这段粘进编辑器，把 your-webhook-url 换成实际地址后保存：


{
  "mcpServers": {
    "wecom": {
      "command": "uvx",
      "args": ["wecom-bot-mcp-server"],
      "env": {
        "WECOM_WEBHOOK_URL": "your-webhook-url"
      }
    }
  }
}
4）确认状态
保存后看 MCP Server 的状态指示灯：

状态	含义
🟢 绿色	连接成功，可正常使用
🔴 红色	配置异常，检查配置内容、命令环境或地址
5）用起来
配好之后用自然语言描述需求就行，WorkBuddy 会自动调用对应的 MCP Server：


请通过企业微信机器人通知：正式产品已发布，请 @张三 进行验收。
适用场景
场景	说明
发布通知	版本上线后自动通知项目群相关人员
任务提醒	把待办、验收、协作事项同步到企微群
流程打通	连接 WorkBuddy 任务处理与外部平台
能力扩展	通过更多 MCP Server 调用丰富的外部服务
最佳实践
配置建议

公共能力配用户级——通知类能力配置一次，多项目复用
专属接入配项目级——独立配置，避免互相影响
从成熟示例起步——先接 WeCom Bot 这种路径清晰的，跑通了再折腾复杂的
描述尽量明确——说清通知对象、内容、是否需要 @，调用效果更稳定
安全提示

妥善保管 WebHook URL——它就是机器人的调用凭证，泄露了任何人都能往你的群里发消息
检查 JSON 格式——配置失败时优先确认括号、引号是否完整。这是最常见的失败原因
关注状态指示灯——绿色可用，红色需排查
插件：把一组能力打包
插件用于打包分发一组相关能力。 一个插件可以同时包含技能、外部工具连接、快捷指令、自动化规则等组件，安装后统一使用。

插件由什么组成
组件	说明	示例
技能（Skills）	教会 AI 完成某类任务的方法与流程	—
MCP 连接	对接外部服务	连接邮箱、网盘
快捷指令（Slash Commands）	在对话框输入简短命令触发功能	输入 /周报 一键生成周报
自动化规则（Hooks）	在特定时机自动执行操作	生成文件后自动检查格式
智能体（Agents）	针对特定任务的专属 AI 助手	—
不同插件包含的组件数量可能不同，但安装与使用方式保持一致。

插件市场
浏览推荐插件，按需一键安装。已安装的可以启用、停用、更新。点插件卡片进行单独管理：

更新——获取插件最新版本
启用 / 禁用——按需开关
插件市场支持关键词搜索。

插件 vs 技能怎么选

需要单一能力 → 装技能。需要一整套配合工作的能力（比如「周报」这件事需要一个技能 + 一个快捷指令 + 一条定时规则）→ 找插件。

插件的价值是省掉你自己组装的功夫，代价是你要一次性接受它带的全部组件。装之前看清楚组件清单。

自定义模型
顺带说一下模型接入，因为它和 MCP 一样属于「把外部东西接进来」这一类。

在设置 → 模型里通过图形界面管理自定义模型，不需要操作配置文件。配置保存后自动持久化；选择标准供应商时，工具调用、图片输入等能力标记会自动写入。

三种接入方式
提供商接入。 从提供商列表中选择，URL、模型列表、能力标记会自动填充，只需补全 API Key。支持腾讯云 Token Plan（个人版 / 企业版多个套餐档位）、各家 Coding Plan，以及主流厂商的预设入口。

本地部署。 接 Ollama——开源的本地大模型运行工具，装好后一行命令拉取并运行开源模型，默认监听 11434 端口，自动提供兼容 OpenAI 协议的接口。适合三种场景：

数据隐私 / 内网合规：代码与对话内容不出本机
零成本试用：不消耗 Token、不用付费 API Key
离线可用：飞机上、内网开发机、没网的环境
自定义。 服务不在列表里，手填 URL、API Key 与模型名。

自定义协议
当模型服务使用非标准 URL 路径（比如经过网关或代理层封装）时，在高级配置里开启「自定义协议」开关：

状态	行为
关闭（默认）	使用标准 /chat/completions 路径，自动校验并补全接口地址
开启	直接使用你填写的接口地址发起请求，跳过路径校验与自动补全
费用不走积分

自定义模型产生的全部费用（Token、订阅）由你向第三方支付。WorkBuddy 只作通信链路，把你的输入直接转发给该模型，输出由该模型直接返回。

使用过程中可能持续触发模型调用，建议密切关注你在第三方的账户费用，避免出现超出预期的支出——这部分开销在 WorkBuddy 的积分账单里是看不到的。

老配置仍然有效

已经通过 ~/.codebuddy/models.json 配置的自定义模型在界面升级后仍可正常使用，并可通过 UI 查看、编辑或删除，不需要再直接操作配置文件。

常见问题
Q：MCP Server 一直是红灯怎么办？

按顺序排查：JSON 格式（括号、引号、逗号）→ command 指定的运行时装了没（uvx、npx 之类）→ URL 或凭证对不对 → 网络能不能到目标地址。

Q：MCP 和连接器是一回事吗？

连接器是产品层的概念，官方连接器背后有一部分就是 MCP 实现的。自定义连接器本质上就是让你接自己的 MCP 服务。你可以把连接器理解成「官方已经帮你配好的 MCP」。

Q：项目级配置会被同步到团队成员吗？

项目级 mcp.json 在项目目录下，跟着项目走。但项目的连接器授权分公共和个人两种，凭据的处理规则不同，见 项目与团队协作。
